# Schema generation

The extension ships JSON Schema validation and completion for Home Assistant YAML files. Schemas are catalogued in
[`src/language-service/src/schemas/mappings.json`](../../src/language-service/src/schemas/mappings.json) and generated by [`index.ts`](./index.ts) (`npm run schema`). The generated output lands in `src/language-service/src/schemas/json/` (gitignored) and is read at runtime by `schemaService.ts`.

## Generators

Two generators produce the schemas from different sources:

| Generator          | Source of truth                                          | Tooling                  |
| ------------------ | -------------------------------------------------------- | ------------------------ |
| `configuration.ts` | Hand-maintained TypeScript types in [`types/`](./types/) | `typescript-json-schema` |
| `lovelace.ts`      | Upstream `home-assistant/frontend` TypeScript            | TypeScript compiler API  |

The upstream source for the integration/config schemas is `home-assistant/core`, which is Python (config schemas are `voluptuous` definitions), so those types cannot be auto-generated and are maintained by hand. Lovelace is special: `home-assistant/frontend` is TypeScript and carries the card/view/dashboard config types directly.

## Supported schemas

### Lovelace dashboards — auto-generated

Derived from the pinned `home-assistant/frontend` release (see `FRONTEND_REF` in `frontend.ts`). Cards and views are discovered automatically, so no mapping entry is needed beyond these three.

| Schema               | Applies to                     | Output                    |
| -------------------- | ------------------------------ | ------------------------- |
| `lovelace-dashboard` | `ui-lovelace.yaml`             | `lovelace-dashboard.json` |
| `lovelace-views`     | `ui-lovelace.yaml/views`       | `lovelace-views.json`     |
| `lovelace-cards`     | `ui-lovelace.yaml/views/cards` | `lovelace-cards.json`     |

## Maintaining schemas

### Add a manually managed schema

1. Add or extend a TypeScript type in `types/` (e.g.
   `types/integrations/core/<domain>.ts`).
2. Add a `{ key, path, file, tsFile, fromType }` entry to `mappings.json`.
3. Run `npm run schema` and verify the generated JSON in
   `src/language-service/src/schemas/json/`.

### Update a Lovelace schema

Lovelace schemas are regenerated from the pinned frontend release. Bump `FRONTEND_REF` in `frontend.ts` (managed by Renovate) to pick up upstream changes. Manually managed hover descriptions live in [`lovelace-descriptions.json`](./lovelace-descriptions.json). Run `npm run schema:check` to catch stale descriptions or card-discovery regressions.
